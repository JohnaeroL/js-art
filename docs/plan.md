# JS-Art Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Оверлей-панель JS-Art, которая правит стили сайта в реальном времени и сохраняет результат в `site/css/js-art.css` через локальный Node-сервер.

**Architecture:** `js-art/server.js` раздаёт `site/`, вставляет в HTML `<script type="module">` панели и принимает `POST /__js-art/save`. Клиент — ES-модули в `js-art/client/`: чистые модули (color, selector, css-writer, model) тестируются в Node, DOM-модули (scan, picker, ui, index) проверяются в браузере. Все правки — массив `{selector, prop, value, ui}`, который сериализуется в один `<style id="js-art-live">` и в сохраняемый файл.

**Tech Stack:** Node ≥ 18 (`node:http`, `node:fs/promises`, `node:test`), ванильный JS (ES2020 modules), Shadow DOM. Без зависимостей.

**Spec:** `docs/superpowers/specs/2026-10-06-js-art-design.md`

## Global Constraints

- Ноль зависимостей: нет `node_modules`, нет сборки; `js-art/package.json` = `{"type":"module"}` + scripts.
- Сервер слушает только `127.0.0.1`; порт по умолчанию `5173`, `--root site`, `--out css/js-art.css`.
- Скрипт панели в HTML на диске не попадает — только инъекция при отдаче.
- Маркер ссылки в HTML: `<!-- js-art -->`; заголовок файла: `/* generated by JS-Art — edit with: node js-art/server.js */`.
- Бэкап: `js-art/history/YYYY-MM-DD_HH-mm-ss.css`; состояние: `js-art/state.json`; `js-art/history/` в `.gitignore`.
- Undo — до 100 шагов. Мобильная шторка при ширине < 560 px. Значение, равное исходному, правкой не является (`k = 1` → правка удаляется).
- Весь UI-текст панели — на русском.
- `localStorage` только для позиции/свёрнутости иконки, всегда в try/catch.

## Review Focus

- Ползунок тянут быстро (60 событий/с): один шаг undo на одно перетаскивание, не 60 → тест `model.begin` в Task 4.
- Сохранение дважды подряд: `<link>` не дублируется, второй бэкап создаётся → тест в Task 5.
- Запрос `/../package.json` или `%2e%2e` к серверу не отдаёт файлы вне `--root` → тест в Task 6.
- Элементы с классами-состояниями (`.reveal.in`, `.active`) — селектор «все такие» не должен включать `in`/`active`, иначе правка пропадёт после смены состояния → тест в Task 2.
- Правки контраста и яркости одного селектора не затирают друг друга (обе в одном `filter`) → тест в Task 3.

### Task 2: selector.js

**Files:** Create `js-art/client/selector.js`, `js-art/test/selector.test.js`

**Interfaces:**
- Produces: `selectorFor(el, mode: 'all'|'one') -> string`; `STATE_CLASSES` (экспортируемый массив: `in, on, active, scrolled, play, held, sent, menu-open, open, is-active`). Работает с любым объектом `{tagName, id, classList (iterable), parentElement}`; для `'one'` нужен также `parentElement.children`.

Правила:
- `'all'`: «смысловые» классы = классы элемента без `STATE_CLASSES` и без префикса `js-art`. Есть смысловой класс → `.первый`. Нет класса, есть id → `#id`. Иначе тег в нижнем регистре, и если у ближайшего предка есть смысловой класс — `.класс-предка тег`.
- `'one'`: от ближайшего предка с id (`#id`) или от `body`, через ` > `, каждый шаг `tag:nth-of-type(n)` (n считается среди сиблингов того же тега). Если у самого элемента есть id → `#id`.
- Классы/id экранируются: символы вне `[\w-]` → `\\` + символ.

- [ ] **Step 1: Failing tests** с фабрикой `mk(tag, {id, cls, parent})`, которая добавляет узел в `parent.children`:
  - `<div class="srow reveal in">` → `'all'` даёт `'.srow'`
  - `<h3>` внутри `.srow` → `'.srow h3'`; `<p>` в `<div>` (без классов) в `<section class="hero">` → `'.hero p'`
  - `<section id="work">` без классов → `'#work'`; `<a class="active">` в `<nav>` без классов в `body` → `'a'`
  - `'one'`: второй `<article>` в `div` внутри `section#work` → `'#work > div:nth-of-type(1) > article:nth-of-type(2)'`
  - `'one'` без предка с id → начинается с `'body > '`
  - класс `md:flex` → `'.md\\:flex'`
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement.** **Step 4: Run** → PASS.
- [ ] **Step 5: Commit** `feat(js-art): css selector generation`.

### Task 3: css-writer.js

**Files:** Create `js-art/client/css-writer.js`, `js-art/test/css-writer.test.js`

**Interfaces:**
- Consumes: ничего.
- Produces:
  - `HEADER` — строка заголовка из Global Constraints.
  - `serialize(edits: Array<{selector, prop, value}>, {header = false} = {}) -> string` — группирует по селектору в порядке первого появления; блок `selector {\n  prop: value;\n}`; блоки разделены пустой строкой; файл заканчивается `\n`. Свойства вида `filter:<fn>` (напр. `filter:contrast`, value `'1.2'`) сливаются в одно `filter: contrast(1.2) brightness(0.9);` в порядке появления. Пустой список → только header (или `''`).
  - `scaleValue(declared: string, k: number) -> string` — `k` округляется до 3 знаков; `k === 1` → `declared`; иначе `` `calc(${declared} * ${k})` ``.

### Task 4: model.js

### Task 6: server.js

**Files:** Create `js-art/server.js`, `js-art/test/server.test.js`

**Interfaces:**
- Consumes: `save` из `lib/save.js`.
- Produces: `createServer({root, out, toolDir}) -> http.Server` (экспорт для тестов); при прямом запуске парсит `--root` (относительно cwd, по умолчанию `site`), `--port` (5173), `--out` (`css/js-art.css`), слушает `127.0.0.1` и печатает `JS-Art: http://localhost:<port>`.
- Маршруты:
  - `GET /__js-art/client/<file>` — из `toolDir/client`
  - `GET /__js-art/state` — `state.json` или `{}`
  - `POST /__js-art/save` — JSON `{css, state}`, лимит 2 МБ (иначе 413), ответ `{ok:true, ...result}` или 500 `{ok:false, error}`
  - остальное — статика из `root`; директория → `index.html`; путь после `decodeURIComponent` + `path.resolve` вне `root` → 403; нет файла → 404
  - в каждый `.html` перед последним `</body>` (без учёта регистра; если нет — в конец) вставляется `<script type="module" src="/__js-art/client/index.js"></script>`
  - заголовок `Cache-Control: no-store`; MIME для html, css, js, json, svg, png, jpg, webp, woff2, ico

- [ ] **Step 1: Failing tests** (сервер на порту 0, временный `root` с `index.html` и `a.css`):
  - `GET /` → 200, тело содержит `/__js-art/client/index.js`; файл на диске не изменился
  - `GET /a.css` → `text/css`; `GET /%2e%2e/package.json` → 403 или 404, но не 200

### Task 7: scan.js и controls.js (DOM-модули)

**Files:** Create `js-art/client/scan.js`, `js-art/client/controls.js`

**Interfaces:**
- Consumes: `parseColor` (Task 1), `selectorFor` (Task 2).
- Produces (`scan.js`):
  - `withOverridesDisabled(fn) -> result` — на время `fn` выключает `#js-art-live` и `link[href*="js-art.css"]` (`sheet.disabled = true`), затем восстанавливает.
  - `declaredValue(el, prop) -> string|null` — inline `el.style` в приоритете; иначе последнее подходящее правило по `el.matches(rule.selectorText)` во всех same-origin листах (исключая js-art), включая `@media` с `matchMedia(conditionText).matches`; кросс-доменные листы пропускаются (try/catch).
  - `rootColorVars() -> Array<{name, value, selector}>` — custom properties из правил, которым соответствует `document.documentElement` (с учётом активных `@media`); `selector` — последнее такое правило; `value` — `getComputedStyle(documentElement).getPropertyValue(name).trim()`; только те, где `parseColor(value)` не `null`.
  - `topBackgrounds(n = 5) -> Array<{color, selectors: string[]}>` — по сумме площадей видимых элементов с непрозрачным фоном, `selectors` = уникальные `selectorFor(el, 'all')`.
- Produces (`controls.js`): `pageControls(scan) -> Group[]`, `blockControls(selector) -> Group[]`, где `Group = {id, label, controls: Control[]}`, `Control = {key, label, kind, selector, prop, min?, max?, step?, unit?, target?}`; `kind` ∈ `'color' | 'scale' | 'length' | 'number' | 'filter' | 'sides'`. Для `'filter'` значение `prop` — `'filter:contrast'` и т.п. (Task 3). Для `'sides'` — `prop: 'padding'|'margin'`, UI раскладывает на `-top/-right/-bottom/-left`.
- Набор контролов и диапазоны — по таблицам «Зона Страница/Блок» спеки. Диапазоны: scale 0.5–2 шаг 0.01; letter-spacing −0.1–0.3 em шаг 0.005; line-height 0.8–3 шаг 0.05; px-длины 0–200 (ширина/высота 0–2000, 0 = исходное); opacity 0–1 шаг 0.01; filter 0–2 шаг 0.01; alpha 0–1 шаг 0.01.

### Task 8: picker.js, ui.js, index.js

**Files:** Create `js-art/client/picker.js`, `js-art/client/ui.js`, `js-art/client/index.js`

**Interfaces:**
- Consumes: всё выше.
- Produces:
  - `startPicker({host, onHover(el), onPick(el), onCancel}) -> stop()` — слушатели в capture-фазе на `pointermove/click/keydown`; клик гасится `preventDefault + stopPropagation`; `host` и его потомки игнорируются; Esc → `onCancel`. Рамка-подсветка рисуется в shadow root панели (`position:fixed` по `getBoundingClientRect`) с подписью-селектором.
  - `mountUI({model, scan, onSave}) -> {setStatus(text, kind), refresh()}` — Shadow DOM-хост `<js-art-root>` в `document.body`; всё по разделу «Панель» спеки.
  - `index.js` — создаёт `<style id="js-art-live">` в `<head>`; `model = new Model(edits => live.textContent = serialize(edits))`; загружает `GET /__js-art/state` (`state.edits` → `model.load`); снимает исходные значения через `withOverridesDisabled`; `onSave`: `POST /__js-art/save` с `{css: serialize(model.list(), {header:true}), state: {version:1, edits: model.list()}}`; при ошибке сети — `navigator.clipboard.writeText(css)` + скачивание `js-art.css` и статус «Сервер не найден — CSS скопирован и скачан».
- Поведение контролов: значение `ui` в правке хранит позицию ползунка (k, px, цвет+альфа). Исходное значение = значение без правки. `input`-событие: при первом за жест `model.begin()`; `change` завершает жест. Значение, равное исходному, → `model.set(..., null)`. ↺ → `begin()` + `set(..., null)`. Scale-контрол пишет `scaleValue(declaredValue(el, prop) ?? computedPx, k)`, где для страницы `el` — первый элемент по селектору.
- Блок: после выбора показывает селектор, переключатель «все такие / только этот», кнопки ↑/↓; исходные значения берутся из `getComputedStyle` выбранного элемента внутри `withOverridesDisabled`.
